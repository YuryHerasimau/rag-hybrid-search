# Архитектура

Документ фиксирует ключевые архитектурные решения и их обоснование. Обновляется
по мере развития проекта.

## Три слоя

```
┌──────────────────────────────────────────────────────────────┐
│  RETRIEVAL (LlamaIndex)                                        │
│  запрос → [BM25]  ┐                                            │
│           [dense] ┘→ RRF fusion → reranker (top-20→top-5)      │
└───────────────────────────────┬──────────────────────────────┘
                                 │ top-k чанков + метаданные
┌────────────────────────────────▼─────────────────────────────┐
│  GENERATION (Claude + Pydantic)                               │
│  чанки → промпт → Claude → структурированный Answer с цитатами │
│  нет опоры в контексте → abstained = true                     │
└───────────────────────────────┬──────────────────────────────┘
                                 │ ответ + привязка к источникам
┌────────────────────────────────▼─────────────────────────────┐
│  EVALUATION (Ragas)                                           │
│  golden-set → метрики → CI-гейт (порог регрессии)             │
└──────────────────────────────────────────────────────────────┘
```

## Почему LlamaIndex + Pydantic, а не «или»

LlamaIndex и Pydantic AI — разные слои, их часто путают.

- **LlamaIndex** — RAG-плумбинг: инжест, node parsers, retrievers, hybrid
  fusion, обвязка reranker. Здесь он силён из коробки.
- **Pydantic** — структурированный вывод генерации со строгой валидацией.

Retrieval делает LlamaIndex; генерацию ответа с обязательными цитатами и
валидацией делает Pydantic-схема. Это и есть анти-галлюцинационный слой, а не
просто промпт «не выдумывай».

## Гибридный поиск и RRF

Скоры BM25 (лексический) и cosine (плотный) несопоставимы по шкале, поэтому
наивное взвешивание скоров плохо работает. Используем **Reciprocal Rank
Fusion** — слияние по рангам, а не по абсолютным значениям. Reranker
(cross-encoder) применяется поверх top-N кандидатов и должен *измеримо* улучшать
метрику — это проверяется в ablation.

## Анти-галлюцинационный слой

```python
class Claim(BaseModel):
    text: str
    source_chunk_ids: list[str]  # обязательно >= 1

class Answer(BaseModel):
    claims: list[Claim]
    abstained: bool  # True, если контекст не даёт ответа
```

Правило: каждый claim обязан ссылаться на реальный `chunk_id` из retrieved-
контекста. Если модель не может привязать утверждение к источнику — abstention
вместо выдумки. Abstention при низком context precision выделяет проект.

## Мультимодальность без локальных моделей

PNG-схемы и макеты из вики прогоняются через **Claude vision** один раз на этапе
инжеста → текстовое описание → индексируется как обычный узел со ссылкой на
исходный файл. Это даёт мультимодальность на CPU-ноуте без запуска тяжёлых
vision-моделей локально; стоимость — разовый расход токенов Haiku на инжесте.

## Ограничения железа

Слабый CPU-ноут без GPU. Следствия:
- корпус держим в разумных рамках (одна вики продукта);
- эмбеддинги кэшируем на диск;
- reranker применяем только к top-20 кандидатам;
- эмбеддинги стартуют на лёгкой `multilingual-e5-small`, апгрейд на `bge-m3` —
  как отдельный пункт ablation по качеству.

## Стоимость и API

Claude вызывается через Anthropic API (pay-as-you-go), **не** через подписку
Claude Pro — Pro не даёт программного доступа к моделям. Расход минимизирован:
эмбеддинги и reranker локальные (бесплатно), captioning и LLM-judge — на дешёвой
Haiku, eval в CI — на подмножестве golden-set.
